Steps to Build

Full roadmap to turn this skeleton into a production-ready estimation tool.

Phase 1 — Foundation

  1. Project setup

    Define folder structure (done). Set up a shared CSS reset and design tokens (colors, spacing, typography).

  2. Navigation & routing

    Implement a lightweight client-side router so the app can switch between pages without a reload. Handle query-string parameters (e.g. ?roomId=abc).

  3. Home page (index.html)

    Build the landing page with a "Create room" form (room name, facilitator name) and a "Join room" form (room code, participant name).

Phase 2 — Core Estimation Room

  1. Room creation & session management

    Generate a unique room code. Persist room state in localStorage (or BroadcastChannel for multi-tab sync). Store the participant list and current user story.

  2. User story queue

    Allow the facilitator to add/edit/remove user stories (title + description). Display the active story prominently during estimation.

  3. Planning Poker card deck

    Render a set of clickable cards with Fibonacci values: 0, 1, 2, 3, 5, 8, 13, 21, ?, ☕. Highlight the selected card; allow changing vote before reveal.

  4. Vote reveal mechanism

    Facilitator clicks "Reveal" to show all votes simultaneously. Hide individual votes until reveal to avoid anchoring bias.

  5. Consensus display

    After reveal, show a summary: each participant's vote, the average (excluding ? and ☕), and a consensus indicator (unanimous / close / split).

Phase 3 — Multi-User Sync

  1. Real-time communication

    Evaluate options: BroadcastChannel API (same browser, multi-tab), localStorage events (same browser), or a lightweight WebSocket server (Node.js / ws). Choose based on whether remote access is needed.

  2. Participant list

    Show all connected participants in real time. Indicate who has voted (✔) vs. who is still thinking (…) without revealing the vote value.

  3. Facilitator controls

    Only the room creator can reveal votes, reset the round, move to the next story, or kick a participant.

Phase 4 — Results & Export

  1. Session summary page (results.html)

    Display all estimated stories with their final agreed point value, round-by-round history, and participation stats.

  2. Export to CSV / JSON

    Let the facilitator download the session results as a .csv or .json file, ready to be imported into Jira or a spreadsheet.

  3. Copy to clipboard

    One-click copy of a Markdown-formatted estimation table to paste directly into a Jira comment or Confluence page.

Phase 5 — UX Polish

  1. Responsive design

    Ensure the card deck and participant list are usable on tablets and smartphones (team members joining from their phone).

  2. Animations & micro-interactions

    Card flip animation on reveal, confetti on unanimous vote, smooth transitions between stories.

  3. Dark mode

    Respect the user's OS preference via prefers-color-scheme and add a manual toggle.

  4. Accessibility (a11y)

    Keyboard navigation for cards, ARIA roles for live regions (vote count, participant list), sufficient color contrast.

Phase 6 — Optional Enhancements

  1. Custom card decks

    Let teams configure their own scales (T-shirt sizes: XS/S/M/L/XL, power-of-2, or custom).

  2. Timer

    Optional countdown per story to keep sessions focused.

  3. Jira integration

    Pre-load user stories from a Jira backlog via API and push story points back on session end.

  4. PWA support

    Add a manifest.json and service worker so the app can be installed as a desktop/mobile app and work offline.
